# V3 categorical matching

The default stage is synthesis.population.matching.matched_v3, selected through
synthesis.population.matched. Explicit matching_algorithm values v1 and v2
continue to select those implementations. Existing private configurations with
an explicit algorithm keep that choice. V1 source is not changed by V3.

## Population and features

V3 reuses V1 get_mz_persons, population_commutes and home_only_mask. It retains
the scenario-day and border filters and uses V1's categorical transformations,
including age, income, car access, commute distance, OVGK, child presence, and
density. The density cut points default to 400, 950 and 1,800 residents/km²,
matching the current V1 intervals; matching_v3_density_bounds can change them.
Raw density remains the resident count within a 2.5 km circle.

Explicit non_private_home_only_households bypass matching and retain donor -1.
Ordinary recipients can receive home-only survey diaries. Collective residents
at municipality centres use only home-only diaries and household survey weights;
ordinary STATPOP recipients use person survey weights. Invalid sampling weights
are excluded with a warning. If a collective recipient cannot be matched, its
household is removed, following V1's household handling.

| Recipients | Hard constraints | Mandatory preferences |
| --- | --- | --- |
| Ages 6–14 | age_class | CHILD_MANDATORY in V3/inputs.py, from V1's child list |
| Ages 15–23 | age_class, employed, car_availability | YOUTH_MANDATORY, from V1's youth list |
| Ages 24+ | car_availability, employed, employment_status | ADULT_MANDATORY, from V1's adult list |

Sex remains a mandatory preference for every group, but is no longer a hard
constraint. A same-sex match is preferred when all mandatory preferences can
be met; sex may differ when the exact mandatory-preference pool is empty.
All other hard fields are unchanged. The opening-hours region is additionally
hard for every group when `consider_opening_hours` is enabled.

Age means the same age class used by V1, not exact age. Ordinary donor pools
are restricted to the corresponding broad age band. Collective donors use the
home-only source pool, as in V1, with the recipient age group's hard constraints.
ARE input supplies age intervals, so its 6–17 class cannot be split at 15:
V3 uses youth hard constraints for ARE classes covering 6–24, and adult hard
constraints thereafter. Its preferences follow V1's ARE attribute list.

## Search and sampling

Runtime logs identify the age group and ordinary/collective donor pool, list
the hard constraints, and report matched recipients, empty hard pools,
preference relaxation and candidate support. The final summary separates
unmatched recipients from additional household removals and home-only bypasses.
Detailed CSV/JSON output paths are logged explicitly.

V1 logs report progress within each cohort or opening-hours region, rather
than calling it population-wide progress. They distinguish complete matches,
relaxed preferences, zero-attribute fallbacks that will be rejected, and empty
region pools. Its final relaxation no longer reports rejected fallbacks as
successful matches. These logging changes do not alter V1's selection rules.

1. Keep only donors matching every hard constraint. Never relax a hard field.
2. Count mismatches on mandatory preferences, excluding hard fields. Choose the
   smallest mismatch count present: zero when any exact mandatory donors exist.
3. Within that mandatory-distance tier, start at zero optional mismatches, then
   allow at most one, two, etc. Stop at the smallest radius giving at least
   matching_minimum_observations donors (default 10).
4. If that tier has fewer than 10 donors even with every optional field relaxed,
   retain the smaller pool and flag below_threshold. Mandatory preferences are
   relaxed only if their exact pool is empty, rather than to manufacture ten
   candidates at the expense of mandatory similarity.
5. Sample one donor from the final cumulative pool proportional to survey
   weight. Donors closer within the pool have no extra probability multiplier.
6. Remove unmatched recipients (or collective households) if the hard pool is
   empty. Missing hard values are not considered compatible.

Every preference disagreement counts once; category numbers have no numerical
distance. Neighbouring and distant bins both count as one mismatch. Unknown
preference categories match the same unknown category. This does not establish
that two unknown values represent genuine behavioural similarity.

Columns may be reordered without changing the selected pool or seeded result.
Hard, mandatory and optional sets express priority explicitly. Donor order is
stabilized by donor ID; uniforms are generated in recipient-ID order outside JIT.
The algorithm matches unique recipient profiles once inside each hard block.
The histogram search and weighted draws use parallel Numba; it stores no full
population-by-survey distance matrix. matching_v3_threads defaults to 8.

Stage outputs retain the usual (mapping, removed_person_ids) tuple. The stage
also writes matching_diagnostics.csv (pool size, mandatory distance, optional
radius, threshold shortfall, removed flag) and matching_report.json. Imported
helper source content is part of cache validation.

## Comparison stage

Select analysis.matching.compare_v1_v3 in a configuration's run list to run or
load both matching stages, then generate a report in
analysis_path/matching/v1_v3/report.html. It requests no simulation run. The
matching inputs include work/education anchors and may require network
preparation if upstream caches are missing or invalidated.
For example, override the existing configuration's run list without editing it:

    uv run -m synpp config_dib_10.yml --run analysis.matching.compare_v1_v3

It compares the top 15 survey-ranked activity chains, distributions of daily
work/education/shopping/leisure/other activity counts (including zero), rates
per 100 residents, start/end times, and completed activity durations. It uses
survey person weights and population donor-reuse weights. It includes both
each algorithm's full retained population and their common recipient set,
with coverage/exclusion counts. Residents below survey age are excluded.
The national report also links to full equivalent reports for Geneva, Zürich
and Vaud, using home-canton IDs checked against data.spatial.cantons. Population
geography follows the recipient's residence; donor residence does not determine
the recipient's canton. Survey comparisons use local survey residents and local
normalization. Re-rendering the national saved report also rebuilds its canton
reports, without either matcher or the spatial stages.

Starts/ends are observed diary times. Initial starts and final ends are censored;
duration distributions therefore use internal, completed activities only.
Invalid/negative/out-of-range timings are counted in exported tables. These
assigned-diary summaries precede downstream changes such as remote work and
trip-purpose recoding. Aggregate survey agreement is descriptive, not proof of
predictive accuracy for the real population.

PNG and PDF figures and all numerical CSVs are saved. Regenerate the report
from those saved tables, without either matcher, with:

    uv run -m analysis.matching.population_comparison /path/to/analysis/matching/v1_v3
